# Полное покрытие администрирования кластера 1С

## Цель

Довести самостоятельные backend, расширение VS Code и MCP до согласованного набора возможностей `rac`, воспроизвести ключевые представления штатной консоли в центральной области VS Code и проверять функции на реально установленных версиях платформы.

## Границы решения

- Источник данных и команд — установленная вместе с платформой утилита `rac`; сторонний backend не используется.
- Backend остаётся единственной точкой запуска процессов, проверки UUID/параметров и преобразования ошибок.
- Расширение получает логин и пароль только при ответе `RAC_AUTH_REQUIRED`, хранит их в VS Code SecretStorage и повторяет запрос один раз.
- Возможности определяются по справке выбранного исполняемого файла. Интерфейс и MCP не должны предполагать наличие команды только по номеру версии.
- Опасные операции требуют явного подтверждения. Удаление регистрации базы не удаляет физическую БД. Восстановление хранилища двоичных данных и очистка места не выполняются неявно.

## Матрица версий

Локально проверены `rac` 8.3.24.1819, 8.3.27.1989, 8.3.27.2214 и 8.5.1.1150.

Общие режимы: `agent`, `cluster`, `manager`, `server`, `process`, `service`, `infobase`, `connection`, `session`, `lock`, `rule`, `profile`, `counter`, `limit`.

В 8.3.27 и 8.5 дополнительно присутствуют:

- `service-setting` — настройки сервисов на уровне кластера/рабочего сервера, применение и получение каталогов для переноса;
- `binary-data-storage` — сведения о хранилище двоичных данных, полные/дифференциальные резервные копии, восстановление и очистка неиспользуемого пространства.

## Представление в VS Code

- Узел кластера содержит базы, рабочие процессы, рабочие серверы, требования назначения функциональности, сервисы, сеансы, соединения, менеджеры, блокировки, профили безопасности, счётчики, ограничения и поддерживаемые новые режимы.
- Узел базы раскрывается в `Сеансы`, `Соединения`, `Блокировки`; выбор открывает отфильтрованную таблицу в центральной области.
- Выбор коллекции открывает центральную таблицу с поиском, счётчиком, обновлением и CSV-экспортом.
- База и рабочий сервер открывают редактируемые карточки; процесс и остальные отдельные записи — структурированную карточку свойств.
- Команды завершения сеанса, разрыва соединения и выключения процесса выполняются только после подтверждения.

## Контракт backend

- `GET .../capabilities` возвращает путь, версию и доступные режимы `rac`.
- `GET .../<resource>` возвращает коллекцию; фильтры базы, сеанса, соединения, процесса и сервера передаются как UUID.
- `GET .../<resource>/<uuid>` использует соответствующую команду `info`, если она поддержана.
- Специализированные mutation-маршруты формируют только разрешённые аргументы `rac`, никогда не используют shell и маскируют секреты.

## Проверка

1. Unit: разбор справки, обнаружение возможностей, маршрутизация и валидация аргументов.
2. Contract: одинаковый REST-контракт для extension и MCP.
3. Integration: read-only обход доступных сущностей на 8.3.24, 8.3.27 и 8.5; unsupported-функции скрыты.
4. Safe E2E: временная регистрация базы, чтение/изменение блокировок и лицензий, сеансы/соединения/блокировки, снятие только регистрации.
5. Visual: Extension Development Host; снимки дерева, таблиц базы/сеансов/соединений/блокировок и карточек процесса/сервера.
