# Управление жизненным циклом RAS — дизайн

## Цель

Позволить пользователю подготовить RAS непосредственно из VS Code, когда сервер администрирования ещё не запущен.

## Режимы

### Приложение

Backend запускает выбранный `ras.exe` как дочерний процесс без консольного окна, ждёт открытия TCP-порта и показывает экземпляр в отдельном дереве VS Code. Такие экземпляры принадлежат backend и гарантированно останавливаются вместе с ним, поэтому после перезапуска не остаются бесконтрольные процессы.

### Служба Windows

Backend создаёт службу через `sc.exe` с командой `ras cluster --service --port=<port> <agent-host>:<agent-port>`. Службу можно установить, запустить, остановить и удалить. Операции изменения службы требуют административных прав; ошибка доступа должна возвращаться пользователю без попытки скрытого повышения привилегий.

## Безопасность

- Пути принимаются только из списка обнаруженных установок `ras.exe`.
- Порты, адрес агента и имена служб валидируются.
- Команды запускаются без shell.
- Backend останавливает только процессы, запущенные им самим.
- Службы имеют предсказуемый префикс `OneC-RAS-` и сохраняются в отдельном state-файле.
- Удаление службы требует явного подтверждения в VS Code.

## API

- `GET /api/ras/installations`
- `GET/POST /api/ras/applications`
- `DELETE /api/ras/applications/{id}`
- `GET/POST /api/ras/services`
- `POST /api/ras/services/{name}/start`
- `POST /api/ras/services/{name}/stop`
- `DELETE /api/ras/services/{name}`

## UI

Отдельное представление «RAS» в контейнере расширения:

- «Установленные версии»;
- «Запущены как приложение»;
- «Службы Windows»;
- команды запуска, установки, остановки, запуска и удаления.

## Проверка

- Unit-тесты построения аргументов и API.
- Реальный запуск RAS 8.3.27 на тестовом порту 4545 для агента `localhost:2540`.
- Проверка подключения через `rac cluster list localhost:4545`.
- Остановка тестового экземпляра и проверка закрытия порта.
- Системная служба в smoke-тесте не создаётся.
