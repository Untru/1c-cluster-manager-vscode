# MCP и полный цикл управления информационной базой

## Цель

Добавить независимый stdio MCP-сервер для агентской разработки и безопасный воспроизводимый E2E-сценарий создания временной базы, изменения административных ограничений и снятия регистрации.

## Архитектура

- MCP использует официальный TypeScript SDK и обращается к самостоятельному REST backend.
- Backend остаётся единственной точкой запуска `rac`, валидации параметров и аутентификации.
- MCP не хранит пароли; локальные секреты передаются переменными окружения.
- UI и MCP используют одинаковые REST-маршруты.

## Безопасность удаления

Удаление информационной базы реализовано только как `rac infobase drop` без `--drop-database` и без `--clear-database`. MCP дополнительно требует литерал `UNREGISTER`. E2E создаёт уникальный контейнер Postgres Pro для 1С и никогда не выбирает существующую базу.

## Полный цикл

1. Создать одноразовый контейнер и уникальную временную БД.
2. Зарегистрировать базу и получить её UUID.
3. Установить `sessions-deny=on`, `scheduled-jobs-deny=on`, `license-distribution=deny`.
4. Прочитать полные свойства и проверить значения.
5. Вернуть `off/off/allow` и повторно проверить.
6. Снять регистрацию с ограниченным retry для краткоживущих внутренних соединений.
7. Подтвердить сохранность физической БД и удалить только одноразовый контейнер.

## Визуальная проверка

Изолированный VS Code запускается через `@vscode/test-electron`, открывает реальное дерево расширения и удерживается для UI Automation и снимков. В репозитории сохраняются снимки временной регистрации и её полных административных свойств.
